## 1. Níveis de esforço e o que a CLI aceita de verdade

- Claude Code, *Commands* — https://code.claude.com/docs/en/commands
  - `/effort [level|auto|status]`: "Set the effort level: `low` to `xhigh`, `max`, `ultracode`, or `auto`;
    `status` prints it. `max` and `ultracode` are session-only; the `ultracode` key persists."
  - `/fast [on|off]`: "Toggle fast mode on or off."
- **MEDIDO 09/09/2026, build 2.1.263** (`evidencias/cli-effort.txt` do ciclo): `claude --effort banana -p`
  **não falha**. Saída: `Warning: Unknown --effort value 'banana' — ignoring it and using the default
  effort. Valid values: low, medium, high, xhigh, max.` e a chamada **roda assim mesmo** (exit 0,
  `total_cost_usd` 0,474985 no teste). Duas consequências que viraram código:
  1. a lista fechada do `modos.py` é `low, medium, high, xhigh, max` — a da CLI, não a da doc;
  2. `ultracode` **não** entra como `--effort` do juiz: é ajuste do executor (`/effort ultracode`).
  Este é o padrão de falha preferido da casa: portão que avisa e deixa passar. Por isso quem valida
  somos nós, antes de montar a linha de comando.

## 2. Ultracode — por que ele é o modo 10, e não o F1

- Claude Code, *Orchestrate subagents at scale with dynamic workflows* — https://code.claude.com/docs/en/workflows
  - "Ultracode is a Claude Code setting that combines `xhigh` reasoning effort with automatic workflow
    orchestration. With it on, Claude plans a workflow for each substantive task instead of waiting for
    you to ask."
  - "This applies to every task in the session, so each request uses more tokens and takes longer than at
    lower effort levels."
  - "A workflow spawns many agents, so a single run can use meaningfully more tokens than working through
    the same task in conversation."
  - Guia de tamanho: "`small` Fewer than 5 agents", "`medium` Fewer than 15 agents", "`large` Fewer than
    50 agents"; "The default is `medium`."
  - Limites do runtime: "Up to 16 concurrent agents, fewer when Claude Code has fewer CPUs available";
    "1,000 agents total per run"; "Up to 4,096 items in a single `parallel()` or `pipeline()` call".
  - Latência do fan-out: "In a fan-out, agents that share the first agent's prompt-cache prefix start up to
    5 seconds after it by default"; "Claude Code caps the hold at `CLAUDE_CODE_WORKFLOW_PREFIX_STAGGER_MS`
    milliseconds, `5000` by default. Set it to `0` to disable the hold."
  - Armadilha para o juiz (que roda em `-p`): o keyword `ultracode` "doesn't start a workflow when it
    reaches the session another way: a prompt passed with `-p`".
- Leitura da casa: "mais tokens **e** mais lento" é exatamente o eixo CERTEZA. Por isso o 10 é o Opala
  (motor grande, bebe, não corre) e o stagger 0 é do F1, não do 10.

## 3. Fast mode — o turbo do F1, e por que ele é DINHEIRO

- Claude Code, *Speed up responses with fast mode* — https://code.claude.com/docs/en/fast-mode
  - "Fast mode is a high-speed configuration for Claude Opus, making the model up to 2.5x faster at a
    higher cost per token."
  - "It uses Claude Opus with a different API configuration that prioritizes speed over cost efficiency.
    You get identical quality and capabilities with faster responses."
  - "Fast mode is supported on Opus 5 and Opus 4.8. It is not available on Sonnet, Haiku, or other models."
  - "For Claude Code users on subscription plans (Pro/Max/Team/Enterprise), fast mode is available via
    usage credits only and not included in the subscription rate limits."
  - "Fast mode usage draws directly from usage credits, even if you have remaining usage on your plan."
  - "The first time you enable fast mode in a conversation, you pay the full fast mode uncached input token
    price for the entire conversation context… enabling fast mode from the start is cheaper."
  - Em `-p`: "`/fast` works only in a session launched with fast mode in its `--settings` value, for example
    `claude -p --settings '{"fastMode": true}'`".
  - Combinação que o F1 usa: "You can combine both: use fast mode with a lower effort level for maximum
    speed on straightforward tasks."
- Leitura da casa: crédito de uso é gasto FORA do limite da assinatura → cai na régua v5 (**dinheiro**).
  Por isso `f1` nasce com `fast=False` e só `modos.turbo()` liga, com escalada obrigatória.
- MEDIDO no mesmo teste: o JSON do `-p` traz `"fast_mode_state":"off"` e
  `"fast_mode_disabled_reason":"sdk_opt_in_required"` — confirma que em `-p` o fast só entra por `--settings`.

## 4. Padrão de skill (o papel do skill-creator)

- Claude Code, *Skills* — https://code.claude.com/docs/en/skills
  - "Keep the body itself concise. Once a skill loads, its content stays in context across turns, so every
    line is a recurring token cost."
  - "Keep `SKILL.md` under 500 lines. Move detailed reference material to separate files."
  - "This keeps `SKILL.md` focused on the essentials while letting Claude access detailed reference
    material only when needed."
  - "Large reference docs, API specifications, or example collections don't need to load into context every
    time the skill runs."
  - "Claude uses this to decide when to apply the skill" (sobre o campo `description`).
- Aplicação nesta v9: a tabela dos 12 perfis mora em `references/modos.md`; o SKILL.md ganhou 12 linhas e
  devolveu 21 movendo o detalhe dos hooks para `references/hooks.md`. O limite desta casa (300 linhas) é
  mais duro que o oficial (500) e continua valendo no `prova.py`.
